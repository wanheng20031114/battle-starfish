# Curling Lab

这是一个与 Battle Starfish 主玩法完全隔离的冰壶板块，包含 2–8 人联机比赛和独立的单人测试沙盒。合法多人阵容为 1v1、1v2、2v2、2v3、3v3、3v4 和 4v4；每队仍投 8 颗壶。冰壶场景、脚本、测试和公网服务文件都位于 `res://curling/`，不与主玩法共享流程或状态。

玩家操作、标线、计分和异常判断参见 [`玩家说明书.md`](玩家说明书.md)。比赛中可点击右侧“说明书”，或按 `F1` 随时查看。

## 运行

- 在 Godot 4.6 中打开 `res://curling/curling.tscn` 并按 F6。
- Windows 也可从仓库根目录运行 `powershell -ExecutionPolicy Bypass -File curling/tools/run_curling.ps1`。
- 主菜单“冰壶”进入多人大厅；“冰壶单人测试”直接进入离线沙盒，不要求用户名，也不会启动 LAN、公网大厅或房间服务。
- LAN Host 使用 UDP `40150`，发现广播使用 UDP `40151`。
- 公网大厅固定指向 `http://47.123.6.127:8010`，可用启动参数 `--curling-api=http://127.0.0.1:8010` 覆盖。

公网测试连接是明文 HTTP 与普通 ENet，不提供传输加密或竞技级反作弊。玩家 Host 持有规则与物理权威，因此理论上可以作弊。

## 操作

- 大厅：创建 LAN 或公网房，或从公开列表、代码房、LAN 地址及快速匹配加入。
- 房间：自行选红蓝队并准备；每队最多 4 人，开赛时人数差不得超过 1。Host 可以在开赛前为任意玩家调队，但不能踢人。
- 战术：点击自己的投壶位认领/释放；每名队员分别确认。无人认领的位置在锁定时公平补齐。
- 出手：从当前壶向后拖拽，短边三分之一达到满力；拖拽时 `A/D` 微调方向、`W/S` 微调力度，按住 `Shift` 慢调；`Q/E` 连续调旋，滚轮按每格 `0.08 rad/s` 微调，旋转上限为 `±2.00 rad/s`。
- 正式比赛瞄准：投壶方全队同步看到当前力度、精确瞄准角和旋转值。冰面只显示细直方向线、短弯曲虚线和垂直旋向箭头；弯曲线与箭头是刻意放大的旋向示意，不预测落点。对方队伍看不到这些参数、线条或投壶者的拖拽光标。
- 入垒推荐：无挡壶时沿中线瞄准 Tee、旋转 `+0.00`、不刷冰，使用 `77%` 力量；`75%` 是精确 Tee 标定。同样力量若持续满刷会多滑约 3.2 米。
- 镜头：未拖拽的非滑行阶段用 `A/D` 或左右方向键沿赛道查看；擦冰阶段自动跟踪本手冰壶。
- 擦冰：投壶方所有在线成员都可按住左键并快速移动鼠标；壶上方实时显示预计剩余时间和擦冰延长量。
- 计时与音效：正式瞄准限时为 60 秒，最后 10 秒逐秒提示且音高递增；投壶、碰撞、擦冰、得分、出界和规则回滚使用独立音色。
- 设置：大厅、房间、比赛右栏和结果页都可打开；任意界面也可按 `Esc`。设置页不会暂停权威计时、物理或网络同步。
- `F3`：显示只读网络/物理诊断。
- `F1`：打开或关闭比赛说明书；只锁住本机操作，不暂停比赛。

## 冰壶单人测试

- 投壶操作、场地、冰壶、碰撞、摩擦、旋转、擦冰热量和音效与正式比赛共用同一套实现。
- 与正式比赛不同，沙盒保留完整的无碰撞轨迹预览和投出后的实际轨迹，便于做物理实验。
- 可随时选择红/蓝壶及左右投掷方向；所有运动壶停稳后才会生成下一壶，历史和编号没有 16 壶上限。
- 点击场上冰壶或历史行可以查看出手参数、位置、速度、路径、摩擦力、弯曲力、热量、碰撞与预计剩余时间；曲线页以 20 Hz 显示当前记录的速度、作用力和热量。
- 可移除当前选中壶；“清空场地”保留历史，“清空历史”会同时清场并把编号重置为 1。
- 沙盒只按正式边界清理出界壶，不执行计分、End、Hog Line 判定、五壶保护或 no-tick 回滚。
- 测试记录仅在当前会话中保留，不存盘、不导出，也不能修改正式物理参数。

显示、主音量、音效音量和降低镜头运动会自动保存到 `user://curling_settings.cfg`。设置实现完全位于 `curling/`，运行时创建独立 `SFX` 音频总线，不需要新增 Autoload 或修改项目设置。

## 目录

- `curling.tscn` / `curling.gd`：独立入口与应用状态机。
- `game/`：原生 `RigidBody2D` 冰壶、冰道、热网格、规则和比赛状态机。
- `sandbox/`：单人测试控制器、会话记录、轨迹与只读遥测图表。
- `network/`：LAN、公网 Relay 协议、204 字节快照、时钟和远端光标。
- `server/lobby_api/`：FastAPI 临时房间、匹配、租约和 HMAC 票据。
- `server/relay_project/`：每房间一个只认证/转发的 Godot ENet Relay。
- `server/deploy/`：独立 systemd 安装与卸载包；本仓库不会自动操作服务器。
- `tests/`：规则、协议、物理标定和可配置为 2–8 人的多人网络烟测。

Godot 会把两份默认非吸收型 `PhysicsMaterial.bounce` 相加，因此单壶资源使用 `0.46`；两壶相撞的实测恢复系数为约 `0.92`。

## 公网本地启动

参见 [`server/README.md`](server/README.md)。测试脚本会跟踪自己启动的 PID，并在退出时只终止对应的无头 Godot 与 Python 进程。

当前游戏协议为 v2；LAN 发现、房间注册、公网票据和 Relay 会拒绝 v1 客户端。HTTP API 路径仍保持 `/v1`。
